# Группировка парковок на карте

Документ описывает фактическое поведение карты ParkTrack и служит спецификацией для мобильного клиента, который должен повторять интерфейс и функциональность веб-карты.

## Термины и входные данные

Каждая парковка (зона) содержит как минимум:

```ts
type Zone = {
  zone_id: number;
  geometry: GeoJSON.Polygon;
  zone_type: 'standard' | 'parallel';
  free_count: number;
  is_active: boolean;
};
```

В расчёт попадают только зоны, загруженные для текущего viewport и прошедшие пользовательские фильтры. Поэтому мобильному приложению не следует кластеризовать весь справочник парковок: сначала нужно ограничить данные текущим bbox карты.

Координаты в API карты имеют порядок `[longitude, latitude]`.

## Константы текущей реализации

| Параметр                        | Значение | Назначение                                      |
| ------------------------------- | -------: | ----------------------------------------------- |
| `CLUSTER_MERGE_PX`              |     `22` | Радиус близости центроидов в экранных пикселях  |
| `CLUSTER_ZOOM_STEP`             |    `0.5` | Шаг обновления кластеров при изменении масштаба |
| `ZONE_BADGE_MIN_ZOOM`           |     `14` | Минимальный zoom для бейджей одиночных зон      |
| `SELECTED_ZONE_ZOOM`            |     `16` | Базовый zoom при выборе парковки                |
| `MAP_MAX_ZOOM`                  |     `21` | Верхний предел zoom                             |
| `CLUSTER_EXPANSION_SEARCH_STEP` |   `0.25` | Шаг поиска распада кластера при нажатии         |
| `CLUSTER_EXPANSION_ZOOM_BUFFER` |   `0.25` | Запас zoom после найденной границы распада      |

Потолок суммы свободных мест зависит от масштаба:

```ts
if (zoom < 7) maxFreeSpots = 1400;
else if (zoom < 10) maxFreeSpots = 350;
else if (zoom < 13) maxFreeSpots = 150;
else maxFreeSpots = Infinity;
```

У неактивной зоны свободные места считаются равными нулю:

```ts
const free = zone.is_active ? zone.free_count : 0;
```

## Алгоритм кластеризации

### 1. Центроид и проекция в пиксели

Для каждой зоны вычисляется центроид полигона. Затем координаты переводятся в Web Mercator world-pixel при текущем `zoom`:

```ts
const scale = 256 * 2 ** zoom;
const x = ((lon + 180) / 360) * scale;
const sinLat = Math.sin((lat * Math.PI) / 180);
const y = (0.5 - Math.log((1 + sinLat) / (1 - sinLat)) / (4 * Math.PI)) * scale;
```

На карте без наклона и поворота расстояние между такими точками примерно равно расстоянию в CSS-пикселях на экране.

### 2. Связные группы по расстоянию

Две зоны объединяются, если расстояние между их центроидами не превышает `22 px`:

```ts
dx * dx + dy * dy <= CLUSTER_MERGE_PX ** 2;
```

Используется single-link/union-find: если A близка к B, а B близка к C, все три зоны входят в одну связную группу, даже если A и C напрямую дальше 22 px.

В реализации используется spatial hash (ячейка размером `mergePx` и 8 соседних ячеек), поэтому не требуется сравнивать каждую пару зон. Это важно для мобильных устройств.

### 3. Разбиение по числу свободных мест

Если связная группа имеет сумму свободных мест больше `maxFreeSpots`, она рекурсивно делится пополам по медиане вдоль более длинной оси bounding box. Разбиение продолжается, пока сумма каждой подгруппы не станет допустимой.

Исключение: одиночная зона не делится даже тогда, когда её собственный `free_count` больше потолка.

```ts
function splitByCap(points, cap) {
  if (points.length <= 1 || sumFree(points) <= cap) return [points];
  const axis = longerAxis(points); // X или Y
  const sorted = sortBy(points, axis);
  const mid = Math.floor(sorted.length / 2);
  return [...splitByCap(sorted.slice(0, mid), cap), ...splitByCap(sorted.slice(mid), cap)];
}
```

Подгруппа из одного элемента не становится кружком кластера: её `zone_id` попадает в `singletonIds`.

### 4. Агрегат кластера

Для подгруппы из двух и более зон создаётся агрегат:

```ts
{
  center: [sumLon / count, sumLat / count],
  freeSum: sum(free),
  zoneCount: count,
  zoneIds: [...ids]
}
```

Центр — среднее арифметическое центроидов зон, а не геометрический центр объединённого полигона.

### 5. Финальное слияние перекрывающихся кружков

После разбиения проверяется, не перекрываются ли визуальные кружки уже на экране. Размер кружка:

```ts
function clusterBubbleSizePx(zoneCount: number) {
  return Math.min(28 + Math.floor(zoneCount / 4) * 4, 44);
}
```

При проверке учитывается внешний ring `2 px` с каждой стороны. Если расстояние между центрами меньше суммы радиусов, два агрегата снова объединяются. Это финальное правило имеет приоритет над потолком `maxFreeSpots`: итоговый кружок может превысить этот потолок, если иначе два визуально перекрывающихся кружка останутся поверх друг друга.

## Когда парковки объединяются и разъединяются

### Объединяются

Кластер пересчитывается, когда меняется:

- набор зон в текущем bbox или применённые фильтры;
- квантованный zoom (`0.5`, например `14.0`, `14.5`, `15.0`);
- режим времени/данные занятости, если он меняет `free_count` или активность зоны.

Во время плавного zoom карта может иметь дробный реальный масштаб, но кластерный расчёт обновляется только на границе очередного шага `0.5`. Это снижает число тяжёлых перерасчётов.

### Разъединяются

Кластер распадается при увеличении масштаба, когда центроиды его участников оказываются дальше порога близости или когда текущая группа проходит другое разбиение по `maxFreeSpots`.

При нажатии на кластер карта не раскрывает его вручную. Она ищет ближайший zoom, на котором все `zoneIds` кластера перестают находиться в одном кружке:

```ts
for (let z = currentZoom + 0.25; z <= maxZoom; z += 0.25) {
  if (!remainsOneCluster(zoneIds, z)) {
    return Math.min(maxZoom, z + 0.25);
  }
}
return maxZoom;
```

Затем выполняется анимация перехода примерно `300 ms` к центру кластера.

При выборе конкретной парковки (тап по полигону или элементу списка) используется другой расчёт: определяется zoom, на котором выбранный центроид удалится от ближайшего соседа больше чем на `22 px`, после чего добавляется запас `0.5`. Итоговый zoom равен максимуму из:

```ts
targetZoom = clamp(max(SELECTED_ZONE_ZOOM, currentZoom, declusterZoom), 0, MAP_MAX_ZOOM);
```

Если два разных объекта имеют совпадающие центроиды, разъединить их геометрическим zoom нельзя; используется `MAP_MAX_ZOOM`.

## Что и где рисовать

### Кружок группы

Кружок рисуется для каждого элемента `clusters`, то есть только для группы с `zoneCount > 1`.

- координаты: `cluster.center`;
- размер: `clusterBubbleSizePx(zoneCount)`;
- текст: `freeSum`;
- цвет: `0 свободных`, `1–2 свободных`, `3+ свободных` — три состояния палитры;
- центрирование: якорь маркера должен быть в центре HTML-элемента (`translate(-50%, -50%)`), иначе он сместится вправо-вниз;
- слой: отдельный marker-layer поверх стандартного features-layer карты;
- нажатие: zoom-in до распада кластера.

Пример мобильного компонента:

```tsx
clusters.map((cluster) => (
  <Marker key={cluster.key} coordinate={cluster.center} anchor="center">
    <ClusterCircle
      size={clusterBubbleSizePx(cluster.zoneCount)}
      color={clusterColor(cluster.freeSum)}
      onPress={() => expandCluster(cluster)}
    >
      {cluster.freeSum}
    </ClusterCircle>
  </Marker>
));
```

### Одиночная парковка

Для `singletonIds` кружок группы не рисуется. Зона отображается своими исходными слоями:

- `standard` — полигон парковки;
- `parallel` — линия/контур парковки;
- бейдж со значением `free_count` — только при `zoom >= 14`.

Важно: исходный полигон должен быть отфильтрован по `singletonIds`, иначе он будет виден одновременно с кружком и появятся дубли:

```ts
const visibleZones = zones.filter((zone) => singletonIds.has(zone.zone_id));
```

На текущей веб-карте `ZoneLayer`, `ParallelZoneLayer` и `ZoneBadgesLayer` используют один и тот же результат кластеризации, поэтому зона не может одновременно считаться одиночкой в одном слое и участником кружка в другом.

## Рекомендуемый жизненный цикл в мобильном приложении

1. Отслеживать `regionDidChange`/аналогичный callback карты.
2. Дебаунсить запрос bbox примерно на `400 ms`.
3. Загружать только зоны текущего viewport.
4. Кластеризовать на UI-потоке только при изменении квантованного zoom и данных.
5. Мемоизировать результат по ключу `(zonesVersion, zoomBucket, filters, timeMode)`.
6. При каждом рендере рисовать либо кружок кластера, либо одиночную зону, но не оба варианта для одного `zone_id`.
7. Тяжёлую кластеризацию для очень больших массивов переносить в background worker/isolate.

Не следует пересчитывать кластеры на каждый кадр жеста масштабирования и не следует монтировать две полноценные карты для desktop/mobile одновременно: на мобильном устройстве это резко увеличивает нагрузку на память, GPU и JS-поток.

## Пограничные случаи и проверки совместимости

- `geometry` без координат пропускается.
- Неактивная парковка участвует в геометрической группировке, но не увеличивает `freeSum`.
- Одиночная парковка с большим числом свободных мест остаётся одиночной.
- При пересечении границы `distance == 22 px` зоны ещё объединяются; для распада требуется строго больше порога.
- При совпадении центроидов разъединение через zoom невозможно.
- Ключ маркера должен быть стабильным и включать состав/размер кластера, чтобы после распада не переиспользовался старый визуальный элемент.
- Для проверки реализации полезны тесты на: цепочку A–B–C (single-link), разбиение по cap, неактивные зоны, совпадающие центроиды, распад по zoom и корректное количество кружков/бейджей.
